## 도둑손 목표 좌표·첫 절도 수정 · 2026-11-13

손의 목표 화면 좌표를 DragLayer가 아닌 손의 부모인 `_root` 로컬 좌표로 직접 변환한다. 레이어의 원점·배율 차이로 생기던 위치 오차를 제거했다. 매 전투의 첫 절도는 배치 조각이 생기면 즉시 접근을 시작하며, 이후에는 저지·절도 완료·목표 무효화 후 기존 15초 주기를 따른다. 모달·포커스에 따른 일시정지는 유지한다.

검증: Assembly-CSharp 빌드 성공(경고 0·오류 0), `git diff --check` 통과. 실제 Play에서 도착 위치·첫 접근 시점·이동/회전 추적·클릭 저지는 아직 확인하지 않았다. 아래 이전 기록의 첫 15초 대기는 이번 변경으로 대체된다.

## TestScene 몬스터 4종 행동 패턴 · 2026-11-12

현재 작업: 기존 적의 ActionCount·수치 배열·EndTurn을 확장했다. 공격·방어·저주 예약·충전을 구분하고 Intent는 공격일 때만 실제 예상 피해를 반환한다. 형상 봉인자는 기존 공격 4 반복, 도둑손은 4/방어 5/10, 저주술사는 저주/충전 +5/기본 4+5=9, 오염술사는 5·오염 3/방어 5/10·오염 5 순환이다. 신규 방어·충전·강한 공격 수치는 임시이며 SpellGame.StartBattle의 배열에서 조정한다. 적 HP는 기존 12를 유지한다.

적 방어는 소모까지 지속하고 적 피격 시 먼저 차감한다. 다음 턴에 자동 해제하지 않는다. 충전은 대입하여 중첩하지 않고 실제 공격 후, 사망·전투 종료 시 정리한다. 저주는 첫 적 행동 후 다음 손패를 대상으로 한 번 예약하며 첫 손패·충전·강한 공격에서는 새로 부여하지 않는다. 실제 시전·망치 분해·실패 피해 10의 기존 추적 경로는 유지한다. 오염 생성은 수량 인자를 받으며 방어 행동에서 호출하지 않는다. 오염 시전 -2·파편 피해 유지·전투 종료 복구는 그대로다.

도둑손의 HasLivingThief·CanAdvanceTheft·UpdateTheft와 타이머·손 이동·저지·절도 복구는 수정하지 않았다. 행동 인덱스와 연결하지 않는다. 적 행동은 EndTurn에서 동기 처리되어 그 동안 UpdateTheft가 실행되지 않는다. 모달에서 기존 일시정지 조건을 재사용한다.

적 의도·상태 설명과 조준 HP 미리 보기는 기존 SpellEnemyView Prefab 참조를 사용한다. 방어 행동은 +수치, 충전·저주는 문자로 구분하고 상세 설명에 다음 행동·현재 방어·충전·절도 패시브를 표시한다. 씬·Prefab·패키지 변경이나 추가 Inspector 연결은 없다.

변경 파일: SpellGame.cs, SpellGameUI.cs, UI/SpellEnemyView.cs, PRD.md, README.md. 새로운 스크립트·자산·테스트·패키지·설정은 만들지 않았다. Git CLI·커밋·push를 사용하지 않았다.

저주 경고와 행동 설명이 겹치는 표시 문제를 발견해 경고를 적 아래의 빈 영역으로 이동했다. 최종 코드로 다시 Play하여 첫 저주 뒤 경고·행동 설명·턴 종료 버튼이 겹치지 않는 것을 확인했다. 적 방어를 차감한 조준 HP 미리 보기와 피해 배지 값도 맞췄으며 이 배지의 마지막 한 줄 변경은 컴파일 확인만 했고 조준 재검증은 하지 않았다. 이번 패턴 Play 구간과 최종 재실행 로그에서 새 C# 예외·Missing Reference 메시지는 발견되지 않았다. Play를 종료했다.

남은 수동 확인: 각 적에서 네 번째 행동까지 실행하고, 도둑손 접근 손 클릭과 Q/E·메뉴 정지/재개를 비교한다. 저주 카드를 실제 망치 분해하고, 오염 카드로 각 공격 유형을 시전한다. 적이 방어·충전 중일 때 처치하여 추가 행동이 없는지 확인한 뒤 승리·다음 전투·재시작에서 원본 덱과 패턴 초기화를 확인한다. 현재 확인한 플레이 결과를 이 미검증 항목의 통과 근거로 사용하지 않는다.

## TestScene 오염술사 구현·검증 · 2026-11-12

작업 대상은 w10-test2, Unity 6000.3.22f1이다. AGENTS.md·PRD.md·README.md와 실제 모델·Prefab UI·3D·드래그 경로를 확인했다. TestScene → Play → 하단 `오염술사`로 기존 하수인과 함께 진입한다. 임시 HP는 SpellGame.StartBattle의 12이며 공격은 매번 5다. 기존 세 테스트 적과 SampleScene 흐름, 3×4 격자·배치 무제한은 유지했다. 실제 시작 덱은 현재 코드의 12장이며 변경하지 않았다.

현재 주문은 불씨(단일 6), 방벽(방어 7), 번개(단일 12·한 방), 유성(전체 10), 섬광(단일 8·한 방), 산탄(타격별 2·최대 6타), 만화경(전체 6·순수), 강타(단일 9)다. 공격 주문도 수호 코팅으로 별도 방어를 얻는다.

공격 피해·방어 경로는 그대로 쓰고 실제 오염술사 공격마다 AddContamination이 고유 ID·IsContaminated를 가진 QuarterTriangle 5장을 드로우에 추가한 뒤 Shuffle한다. HP 피해 0 여부와 무관하다. 상한은 없고 소유 덱에는 추가하지 않는다. CopyCard는 오염을 보존하며 개발자 영구 덱 복사는 거부한다. 더미 요약도 일반 카드와 분리한다. FinishCombat과 StartBattle의 기존 전체 전투 영역 정리·소유 덱 복구를 재사용하므로 도형 모양으로 일반 카드를 삭제하지 않는다.

Evaluate는 해당 도안 참여 카드만 세어 기존 코팅·인장·키워드 계산 후 공격·방어에서 장당 2를 빼고 최소 0으로 제한한다. 사용자 확정대로 산탄은 매 타격 감소, 파편 인장 별도 피해는 유지한다. 광역은 감소한 값을 각 적에게 사용한다. 드로우·회수는 유지한다. 실제 Cast와 FormulaText 미리 보기가 Evaluate를 공유한다. 접착 선택·확정은 GlueCardIssue로 오염을 거부하며 이는 임시 프로토타입 규칙이다. 망치는 기존 최소 크기 제한을 재사용한다.

변경 파일: SpellGame.cs, SpellGameUI.cs, SpellTable3D.cs, UI/SpellEnemyView.cs, PRD.md, README.md. 새 Prefab·이미지·스크립트·meta·Inspector 연결은 없다. 씬·패키지·프로젝트 설정은 수정하지 않았다. Git CLI·커밋·push·테스트 코드·프레임워크·테스트 자산 추가는 수행하지 않았다.

실제 검증:

- 통과: Unity 참조·컴파일 옵션으로 게임 C# 컴파일. 오래된 응답 파일의 누락된 SpellPileTileView를 포함해 컴파일했고 Unity 새로고침·Play 진입도 확인했다. 마지막 변경 후 현재 응답 파일로 재컴파일 통과.

이번 Play 이후 로그 구간에서 새 C# 예외는 발견되지 않았다. 이전 로그에는 SpellTable3D.IsOverControl의 NullReferenceException이 있으나 이번 실행에서는 재현되지 않았다. Play는 종료했다. 추가 수동 확인은 오염 카드로 각 효과 유형을 시전하고 Q/E 진입·거부, 완전 방어, 승리 후 다음 전투에서 오염 제거·일반 및 보상 보존 순으로 수행한다. 코드 검토를 실제 Play 통과로 간주하지 않는다.

Unity 6000.3.22f1의 Windows PC용 턴제 도형 주문 덱빌딩 프로젝트다. 물리 낙하하는 작은 3D 손패 조각을 집어 공유 3×4 격자의 도안을 채우고 주문을 시전한다. 일반 전투 다섯 번과 보스 전투를 진행하며 저장 기능은 없다. `Assets/Scenes/SampleScene.unity`를 열고 Play를 누르면 타이틀이 열린다.

## 다른 에이전트의 시작 순서

1. [AGENTS.md](AGENTS.md)의 저장소 작업 규칙을 따른다. Git CLI 사용과 커밋·push는 금지되며 커밋 메시지만 제안한다.
2. [PRD.md](PRD.md) 1~12절과 14~15절에서 현재 규칙과 수용 기준을 읽는다. 13·16절은 과거 계획 이력, 17절은 후속 변경 기록이다. 과거 기록과 현재 본문이 충돌하면 현재 본문을 따른다. 최신 사용자 요청은 문서보다 우선한다.
3. 아래 코드에서 실제 상태를 확인한다. 요구사항, 구현, 검증 결과를 구분하고 이전 버전의 성공을 현재 변경의 검증으로 재사용하지 않는다.

## 현재 규칙과 조작

- 손패 조각을 도안에 드래그하거나 선택 후 클릭해 놓는다. R·우클릭으로 회전하며 배치 횟수 제한은 없다. 턴 시작 시 손패 한도 7장 내에서 5장을 뽑는다.
- 현재 턴 미시전 조각은 이동·회수할 수 있다. 이전 턴 조각과 발동 후 남은 잔상은 고정되며, 고정 조각이 있는 도안도 이동·회전할 수 없다. 도안 비우기는 현재 턴 미시전 조각을 손패로, 고정 조각을 묘지로 보낸다. 손패 한도를 넘으면 비우지 않는다.
- 불씨 피해 6, 방벽 방어 7, 번개 단일 피해 12, 유성 전체 피해 10이 기본이다. 완성 도안은 수동 시전한다. 단일 대상 주문은 생존 적이 하나일 때 클릭하면 즉시 시전되고, 여럿이면 적을 선택한다. 시전 버튼에서 적으로 드래그할 수도 있다.
- 불꽃은 공격 피해 +2, 수호는 방어 +3, 공명은 면적 3칸 이상 시전 후 조각 1장 뽑기, 잔상은 첫 시전 후 한 번 유지된다. 공명 드로우는 손패 한도에 따른다.
- 도안에 마우스를 올리면 설명을 보고, 더보기 메뉴에서 도안을 비울 수 있다. 드로우 덱·묘지를 클릭하면 내용을 확인한다. Esc는 메뉴를 연다.
- 온보딩은 사용자 요청으로 일시 비활성화다. `SpellGameUI`의 `ONBOARDING_ENABLED`를 켜기 전에 현재 규칙과 UI에 맞춰 수정·검증해야 한다.

## 3D 테이블 설정

`SampleScene > Spell UI > SpellTable3D`에 3D 테이블 프리팹 참조가 연결되어 있다. 추가 Inspector 연결은 필요 없다. `Camera Angle`의 기본값 90은 완전한 탑뷰이며 Play 중 75로 바꾸면 약한 사선 화면을 확인할 수 있다(범위 55~90).

- 화면 배치: `Assets/Prefabs/UI/SpellCombatScreen.prefab`을 열어 플레이어, 드로우 덱, 묘지, 버튼과 적 슬롯의 RectTransform을 편집한다. 적은 3개 슬롯 위치를 기준으로 1~3마리를 배치한다. 도안 이름표와 시전 버튼은 격자를 따라 자동 배치한다.
- 판·손패 위치: 같은 프리팹의 `Board`, `Hand Drop Area` RectTransform 중심이 각각 판과 손패의 화면 위치 기준이다. 이들은 표시용 패널이 아니며 크기는 위치 기준 중심을 계산할 때만 쓴다. `Hand Drop Area`는 비활성 상태이므로 Hierarchy에서 선택해 수정한다.
- 3D 크기: `Assets/Prefabs/SpellTable3D.prefab`의 `Grid 3 x 4 > Board slab`에서 **Scale X**를 수정하면 시작 시 3×4 정사각 격자와 조각 크기가 함께 바뀐다. Scale Z는 칸 비율에 맞춰 자동 계산되고 Scale Y는 판 두께다. `Physical Hand > Hand tray`의 Scale X·Z는 손패 받침과 예약 자리 간격·회수 영역을 바꾼다. 두 받침의 위치는 위 HUD 기준 영역에서 지정한다. 부모의 Scale은 (1, 1, 1)을 유지하고, 변경은 Play 시작 전에 저장한다.

손패는 카드 UI 없이 입체 조각으로 표시하며 정사각형 조각의 변 길이는 격자 한 칸과 같다. 마우스를 올리면 이름·특수 효과 설명이 뜬다. 집을 때 현재 물리 yaw에 가장 가까운 배치 가능 90도 방향을 고르고 크기는 유지한다. R·우클릭으로 추가 회전한다. 손패 조각은 실제 Rigidbody·볼록 MeshCollider로 낙하·반동한다. 예약 자리의 수평 이동과 X/Z 기울기를 제한하고 높이와 yaw는 물리로 움직인다. 주문 배치·점유는 물리가 아닌 기존 마스크 판정이다.

테이블 프리팹을 런타임에 인스턴스화하고 카메라·격자선·도안·조각을 생성하며 레이어 30을 사용한다. HUD는 기존 uGUI를 유지한다. 이전 손패 카드·2D 판·기존 작업대/전장 배경은 비활성화한다. 도안과 시전 버튼의 위치, 적의 체력·의도 등 상태 표시는 게임이 갱신한다.

## 2026-11-11 망치 모드 구현 및 검증 상태

E → 손패 일반 조각 클릭 → 오른쪽 왕복 게이지에서 Space 타격 → 결과 표시 → 전투 복귀를 구현했다. 타격 전 Esc는 무료 취소이고, 일반 전투의 R·우클릭 회전 및 Esc 메뉴 경로는 유지한다. 외부 이미지 없이 uGUI 메시로 원형 나무판을 그리고 패널로 망치, 충격선, 조각 펼침을 연출한다. 추가 Inspector 참조 연결은 없다.

모델은 원본 손패 카드를 제거하고 고유 ID의 일반 결과 카드로 교체한다. 직사각형 → 정사각형 2장, 정사각형 → 반칸 삼각형 2장, 반칸 삼각형 → 1/4 삼각형 2장이다. 기존 점유 비트에서 정사각형 15는 반칸 3과 12로, 반칸 3은 1/4의 1과 2로 재구성되며 회전으로 보완 방향을 사용할 수 있다. 새 도형이나 효과를 추가하지 않았다.

타격 실패를 제거했다. 유효한 대상은 강도와 무관하게 반드시 한 번 분해된다. 이후 각 자식을 강도 × 90% 확률로 추가 분해하고 추가 분해되지 않은 자식은 그대로 남긴다. 강도 0%는 기본 분해만, 강도 50%는 자식별 추가 분해 45%, 최대 강도는 자식별 추가 분해 90%다. 따라서 정사각형·반칸·1/4이 섞일 수 있다. UI는 기본 분해 보장, 자식 추가 분해 확률과 최대 결과 수를 표시한다. 게이지 색 구분은 확정 결과의 경계가 아니다. 게이지 편도 이동 시간은 1.4초에서 0.25초로 줄여 약 5.6배 빨라졌고 왕복은 0.5초다.

원본을 교체한 손패 7장 이내에서 일부 자식을 추가 분해한다. 직사각형에서도 정사각형 1장+반칸 1장+1/4 2장 등 면적이 보존된 혼합 결과가 가능하다. 이 조합에는 최소 4장 공간이 필요해 타격 전 손패가 4장 이하여야 한다. 직사각형 전부를 1/4 8장으로 만드는 결과는 전투 제한상 불가능하다. 유효 타격은 턴당 1회 사용을 소비하며 배치 3회와는 별개다. 특수 카드도 분해하며 접착하지 않은 최소 조각은 추가 분해할 수 없다. 횟수·확률 공식·대상·지속·취소 정책은 PRD 16절의 프로토타입 가정이다.

게이지 속도·연출 시간은 SpellGameUI의 망치 프로토타입 설정 필드로 조정한다. Bootstrap이 컴포넌트를 동적으로 생성하므로 Play 중 Inspector 변경은 해당 실행에만 적용된다. 기본값을 지속적으로 변경하려면 필드 초기값을 변경한다. 턴당 사용 횟수는 SpellGame의 HAMMER_USES_PER_TURN, 최대 조각별 성공 확률은 MAX_DECOMPOSITION_CHANCE 상수다. UI 미리 보기는 난수를 소비하지 않는다.

상점 재사용을 위해 공통 계산 SpellGame.DecomposeShape(shape, strength, maxPieces, random)를 공개한다. 반환값은 혼합 Shape 배열이며 카드·전투·덱 상태를 변경하지 않는다. 최대 결과 수와 난수원은 호출자가 전달한다. 전투의 TryHammer만 손패와 사용 횟수를 변경하며, 향후 상점은 비용과 소유 덱 적용을 별도로 처리하면 된다. 상점 화면이나 영구 덱 변환은 이번에 구현하지 않았다.

카드 변환은 Space 입력 시 원자적으로 확정하고 애니메이션은 확정된 결과만 표시한다. 연출 중 UI 재생성·비활성화에도 카드가 재생성되지 않는다. 원정 소유 덱은 수정하지 않아 같은 전투에서는 결과가 버림·드로우로 유지되고 다음 전투에서는 원본 덱으로 복귀한다.

실제 확인 결과:

## 2026-11-11 Q키 접착 구현

TestScene의 기존 Bootstrap을 유지하고 Q 또는 접착 버튼으로 작업대를 연다. 일반·특수 기본 도형 카드 두 장을 클릭하거나 손패에서 작업대로 드래그해 선택한다. 중앙 8×4 작업 공간에서 드래그·칸 스냅·R 또는 우클릭 회전으로 실제 변을 맞춘 뒤 확인한다. 빈 칸 클릭으로도 이동하며 회전 버튼을 제공한다. 조각 전체가 작업 공간 안에 남도록 이동·손패 드롭·회전 후 위치를 제한한다. 두 장 미선택·재접착·겹침·꼭짓점 접촉·틈은 거부하며 이유를 표시한다. Esc 또는 취소는 무료다. 접착과 망치를 동시에 열거나 접착 중 Space로 확정할 수 없다.

접착 카드는 기존 네 가지 기본 도형과 별도의 새 Shape enum이 아니라 선택적 GluedShape 데이터로 표현한다. 원본 두 카드 참조와 ID, 각 회전, 상대 위치, 정규화한 점유 마스크를 보관한다. 기본 카드와 복합 카드의 실제 렌더링·선택·배치·미리 보기·완성 판정은 공통 CellMask를 사용한다. 삼각 구역이 겹치지 않으면서 같은 칸의 인접 구역 또는 이웃 칸의 마주 보는 변을 공유해야 하므로 빈 공간을 채우거나 꼭짓점 접촉을 접착으로 취급하지 않는다.

확인 시 손패 카드와 접촉을 다시 검증해 원본 두 장을 한 장으로 교체한다. 접착 자체는 배치 횟수를 소비하지 않고, 전체를 도안에 배치할 때 1회 차감한다. 이동·회수·미시전 환불도 카드 하나 기준이다. 턴당 접착 1회이며 망치 사용권과 별개다. 같은 전투의 버림·다시 뽑기에서 합성 정보는 유지된다. 원정 소유 덱을 수정하지 않으며 전투 승리·패배·타이틀 복귀 시 임시 전투 카드와 배치를 정리하고 보상 카드를 포함한 소유 덱으로 복구한다. 다음 전투와 재시작에서 복합 카드가 남지 않는다.

원래 도안에 맞지 않는 긴 모양을 붙일 수도 있다. 해당 카드는 실제 전체 영역이 맞는 도안에서만 배치 가능하며 임의로 축소하지 않는다. 접착 카드는 재접착에서 제외하지만 망치로 분해할 수 있다. 기본 타격으로 두 구성 조각을 분리하고 강도에 따라 각 조각을 추가 분해한다. 1/4 둘을 붙인 카드도 해제 가능하며 손패 7장과 면적을 보존한다. 망치 화면의 대상·손패 아이콘도 실제 복합 마스크로 표시한다. Inspector에서 연결할 참조는 없으며 씬·패키지·입력 설정을 변경하지 않았다.

변경 파일은 SpellGame.cs, SpellGameUI.cs, SpellBoardGraphic.cs, SpellShapeGraphic.cs, 신규 SpellGlueGraphic.cs와 .meta, PRD.md 및 README.md다. 테스트 코드·프레임워크·자산은 추가·수정하지 않았다. 새 Windows 빌드는 생성하지 않았다.

수동 확인 예시: 시작 손패의 정사각형과 1/4 삼각형을 선택한다. 정사각형 아래 칸에 위쪽을 점유하는 1/4 삼각형을 붙여 확인하고, 결과 카드 하나를 방벽의 위 칸에 배치하면 전체 도안이 완성되어 배치 1회로 방어 7을 시전할 수 있다. 회수·턴 넘김·재접착 거부·다음 턴 사용권·재드로우·전투 종료 원복도 이어서 확인한다. 보완 반칸 둘은 같은 칸에서 회전을 2회 차이로 맞추면 정사각형 모양으로 접착 가능하고, 마주 보는 1/4 둘은 중심 꼭짓점만 만나므로 같은 칸에서 접착 불가여야 한다.

최소 검증 결과:

- 새 작업 공간 그래픽을 포함한 게임 C# 컴파일 통과. 스크립트 .meta 누락과 Assets 내 중복 GUID 없음. Unity 자산 새로고침 후 TestScene Play Mode에서 최신 접착 UI와 전투를 실행했다.

- 확인 후 손패 5장→4장, 접착 사용권 1→0, 기본 배치 3회 유지. 복합 카드 전체를 방벽에 배치해 도안 완성과 배치 3→2를 확인했다.
- 복합 카드를 한 장으로 회수해 배치 2→3 환불, 같은 카드 재배치 후 방벽 수동 시전으로 방어 7·버림 1·제작 중 0을 확인했다. 다음 턴 체력 50·방어 0·배치 3·접착 사용권 1·5장 드로우도 확인했다.
- 자동 조작의 Q 키와 드래그로는 진입·이동이 관찰되지 않았다. 원인은 확정하지 않았으며 Q·R·Esc·Space의 실제 키 수신 및 드래그는 미검증이다. 위 이동·회전 검증은 빈 칸 클릭과 회전 버튼으로 진행했다.
- 사용자의 최소 검증 요청에 따라 추가 조합·다른 해상도·전투 완주·접착 카드 재드로우·전투 종료 원복·보상 보존·재시작·잔상 및 망치 회귀 조작은 추가 실행하지 않았다. 이 항목들은 구현 경로 검토와 실제 플레이 통과를 구분한다.

후속 수정: 손패 카드에 기존 SpellCardDrag를 연결하고 접착 모달의 드롭 경로를 추가했다. 작업 공간 드래그는 임계 거리를 넘은 현재 포인터가 아닌 최초 pressPosition으로 잡은 조각을 찾도록 수정했다. 이전에는 조각이 격자 밖으로 그려지지만 해당 영역에서는 UI 레이캐스트를 받지 못해 다시 잡을 수 없었다. 모든 이동과 회전에 도형 크기를 반영한 경계 제한을 적용해 밖으로 나가지 못하도록 변경했다. 접착 카드 망치 분해도 연결했다. 이 후속 변경은 C# 컴파일 통과만 확인했고, 최소 검증 요청에 따라 Play Mode를 추가 실행하지 않았다.

접착 작업대에서 드래그 중 R은 현재 잡은 조각을 회전한다. 잡은 지점도 함께 회전시켜 포인터가 정지해 있어도 점유·접촉 표시를 즉시 갱신하며 경계 제한을 유지한다. 손패에서 작업대로 드래그하는 도중에도 미리 보기를 회전하고 드롭 시 방향을 보존한다. 이 변경은 C# 컴파일 통과만 확인했으며 실제 드래그 중 키 입력은 미검증이다.
